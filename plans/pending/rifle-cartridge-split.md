# Отдельные профили оружия и патронов

Статус: выполнено, ждёт мерджа (допущения A1–A8 подтверждены 2026-10-05).
Ветка: `rifle-cartridge-split` (от master после мерджа #21), один PR.

## Проблема

Экран «Профиль» редактирует винтовку, прицел, патрон и пулю одной формой, и
каждый профиль создаёт свои копии `rifle`/`scope`/`cartridge`. Один патрон
нельзя использовать с двумя винтовками, у винтовки нельзя держать несколько
патронов без дублирования.

## Решения (подтверждены 2026-10-05)

| # | Вопрос | Решение |
|---|---|---|
| D1 | Модель | Два независимых списка «Оружие» и «Патроны»; расчёт идёт для пары винтовка+патрон |
| D2 | Прицел | Часть карточки оружия (одна винтовка = один прицел) |
| D3 | Навигация | Нижняя вкладка «Оружие» с табами «Оружие \| Патроны»; на экране «Решение» два выпадающих списка |

## Допущения (на подтверждение)

| # | Допущение |
|---|---|
| A1 | **Пристрелка (дальность нуля + условия пристрелки) — в карточке оружия**, как в Strelok Pro. Для пары хранятся только сдвиг СТП этого патрона относительно нуля (вверх/вправо, см) и коэффициенты уточнения V0/сопротивления. |
| A2 | Журнал выстрелов и уточнение — по паре (V0 зависит и от ствола, и от патрона). Экран «Уточнение» показывает пару и её сдвиг СТП. |
| A3 | Пара создаётся автоматически при первом выборе винтовки+патрона (сдвиг 0, коэффициенты 1). Пользователь пары как отдельную сущность не видит. |
| A4 | Список патронов на «Решении» — все патроны, сначала совпадающие по калибру с винтовкой. |
| A5 | Удаление винтовки/патрона удаляет её пары с журналами выстрелов, после подтверждения в диалоге. |
| A6 | Миграция: каждый существующий профиль → винтовка (с его прицелом и нулём) + патрон + пара. Ничего не теряется, журналы и уточнения сохраняются. |
| A7 | Обмен файлами: экспорт/импорт отдельно винтовки (`balcalc-rifle`) и патрона (`balcalc-cartridge`); старые файлы `balcalc-profile` v1 по-прежнему импортируются (разбиваются на винтовку+патрон). |
| A8 | CLI: `--profile N` остаётся (N = пара); добавляются `--rifle`/`--cartridge`, `profiles` показывает «винтовка / патрон». |

## Never (вне объёма)

- Несколько прицелов на винтовку, отдельный список прицелов.
- Синхронизация/облако, Bluetooth.
- Изменения физики/решателя.

## Фазы

### 1. Схема v3 и миграция — S
- `rifle`: + `scope_id`, `zero_range_m`, `zero_altitude_m`, `zero_pressure_pa`,
  `zero_temperature_k`, `zero_humidity`, `zero_powder_temp_k`.
- `profile` пересобирается (12-шаговая процедура SQLite): остаются `rifle_id`,
  `cartridge_id`, сдвиги СТП, коэффициенты; UNIQUE(rifle_id, cartridge_id).
- `LoadProfile` берёт прицел и нуль из винтовки.
- Файлы: `storage/src/schema.cpp`, `storage/src/database.cpp`, `records`,
  `repository.cpp`, `solution.cpp`.
- Проверка: `storage_*` тесты + новый тест «v2-база с 2 профилями → v3,
  поправки на 300/800 м совпадают до и после».

### 2. applogic: формы винтовки, патрона, пары — M
- `RifleForm` (винтовка+прицел+нуль), `CartridgeForm` (патрон+пуля, логика
  библиотечной/своей пули из `ProfileForm`), `EnsurePair`, удаление с каскадом.
- `ProfileForm` удаляется; `CreateSampleProfile` → пример винтовки+патрона+пары.
- `profile_io`: rifle/cartridge JSON + импорт v1.
- Проверка: `applogic_*` тесты, переписанные под новые формы.

### 3. Backend + CLI — S
- Свойства `rifles`, `cartridges`, `currentRifleId`, `currentCartridgeId`;
  invokables для форм; пара вычисляется из выбора.
- Проверка: `cli_test`, ручной `bal-cli profiles/table`.

### 4. QML — M
- `ArmoryPage` (табы Оружие|Патроны), `RifleEditor`, `CartridgeEditor`
  (из `ProfileEditor`), два выпадающих списка на `SolutionPage`, сдвиг СТП на
  `TruingPage`; переводы uk/ru.
- Проверка: `tests/ui` (обновлённый `tst_flow`), скриншоты desktop + эмулятор.

### 5. Выпуск — XS
- PR, зелёный CI, APK на эмулятор.

## Отклонения от плана

- Заводские патроны стартовой базы (69 из `.ammo`) не попадают в «мои
  патроны»: они в отдельном списке «Скопировать заводской патрон…», копия
  становится своей (сохраняет замеры скорости и длину ствола).
- `profile.scope_id` остаётся неиспользуемой колонкой: SQLite не удаляет
  колонку с внешним ключом, а пересоздание таблицы в транзакции с
  включёнными FK стёрло бы журнал выстрелов каскадом.
- Сдвиг СТП пары редактируется на экране «Журнал выстрелов и уточнение».

# Баллистический калькулятор v1 — план

Статус: **УТВЕРЖДЁН 2026-10-04** · Создан: 2026-10-04

## Цель

Свой баллистический калькулятор для стрелкового оружия (дистанции до 2500 м)
уровня Strelok Pro / Applied Ballistics / Lapua Ballistics / «Стрілець»:
один C++-движок, одно приложение под **Windows, Ubuntu, Android**,
хранение данных в SQLite через обёртку `sqlite_manager`.

### Измеримые критерии успеха v1

1. Для эталонных патронов (.308 175gr SMK G7, 6.5CM 140gr ELD-M G7, .338LM 300gr,
   .50BMG 750gr A-MAX, 5.56 M855 G1) расхождение с эталоном
   (py-ballisticcalc / JBM) при одинаковых входных данных:
   падение и снос ≤ **0.01 MRAD** на всей дистанции 0–2500 м,
   время полёта ≤ 0.1 %, скорость ≤ 0.1 % («как можно точнее» — D11).
   Численная сходимость: уменьшение шага интегратора в 4 раза меняет
   результат на 2500 м не более чем на 1 мм.
2. Расчёт таблицы 0–2500 м с шагом 10 м < **50 мс** на среднем Android-телефоне.
3. Один и тот же бинарный формат БД открывается на всех трёх ОС.
4. Сборки собираются одной командой (CMake preset) для `windows-msvc`,
   `linux-gcc` (Ubuntu 24.04, через WSL/CI) и `android-arm64` (APK).

## Архитектура

```
bal_calc/
├── core/          ballistics_core — чистый C++17, без Qt и без БД
│                  (атмосфера, drag-таблицы, интегратор, пристрелка, эффекты)
├── storage/       ballistics_storage — C++17 + sqlite_manager
│                  (схема, миграции через PRAGMA user_version, репозитории)
├── cli/           bal-cli — отладка/сверка движка, расчёт из профиля в БД
├── app/           Qt 6.9 / QML (Qt Quick Controls 2) — Windows, Ubuntu, Android
├── tests/         GoogleTest: физика vs эталоны, storage на :memory:
├── data/          seed.sql — стартовая библиотека пуль/патронов
├── third_party/sqlite_manager   (git submodule)
└── plans/
```

Зависимости слоёв: `app → storage → core`, `app → core`; `core` ни от чего
не зависит (тестируется изолированно, переносим куда угодно).

### Модель (core)

- **Point-mass 3-DoF** (как у всех перечисленных приложений), интегратор RK4
  с адаптивным шагом по времени; вычисление до 3000 м с запасом.
- Drag: G1, G2, G5, G6, G7, G8, GS + **пользовательская кривая Cd(M)**
  + **многоскоростной BC** (BC по диапазонам скоростей, как в Strelok/Lapua).
- Атмосфера: ICAO + фактические T/P/влажность, высота над уровнем моря,
  плотность и скорость звука; режим «станционное давление» и «приведённое к морю».
- Ветер: до 5 зон по дальности (скорость + направление), вертикальный ветер.
- Угол места цели (стрельба вверх/вниз), кант оружия.
- Кориолис + Этвеш (широта, азимут стрельбы).
- Деривация (Litz, по Sg), устойчивость по Миллеру (Sg) с поправкой на
  плотность/скорость, аэродинамический прыжок от бокового ветра.
- Термочувствительность пороха (таблица V0(T) или коэффициент %/°C).
- Пристрелка: дальность нуля, высота прицела, условия пристрелки ≠ условия
  стрельбы; смещение нуля (zero offset).
- Вывод: падение/снос в см, MRAD, MOA, кликах (цена клика по осям),
  скорость, энергия, время полёта, число Маха; отметки транс/дозвука.
- **Корректировка (truing)**: подгонка V0 или коэффициента BC/кривой по
  фактическим поправкам на 1–3 дальностях (ключевая фича AB/Strelok).

### Данные (storage)

Таблицы: `rifle` (ствол: шаг нарезов, направление, высота прицела, нуль),
`scope` (единицы, цена клика, сетка), `bullet` (масса, калибр, длина,
BC/drag-модель), `drag_curve` + `drag_point`, `bc_band`, `cartridge`
(пуля + V0 + термочувствительность), `profile` (rifle+scope+cartridge),
`reticle` + `reticle_element` (линии/точки/подписи в MRAD/MOA), `conditions` (сохранённые условия), `dope_log` (фактические выстрелы для
truing), `app_setting`. Миграции — нумерованные SQL-скрипты, версия в
`PRAGMA user_version`, применяются в `Transaction`.
Импорт/экспорт профиля — JSON-файл.

Стартовая библиотека (seed) из двух источников:
1. Опубликованные производителями G1/G7 BC, масса, длина для ~40–60 популярных
   пуль (5.45, 5.56, 7.62×39/51/54R, 6.5CM, .300WM, .338LM, 12.7×99/108).
2. Импорт из `Data/libs`: патроны `*.ammo` и сетки `*.reticle`
   (BallisticCalculator1, LGPL-2.1 — с атрибуцией в About) и drag-кривые `*.drg`
   (Exterior Ballistics). Импортёры `.ammo`/`.drg`/`.reticle` также доступны
   пользователю в приложении.

### UI (app)

Экраны: **Профили** · **Условия** (атмосфера, ветер, угол, широта/азимут)
· **Решение** (одна цель: поправки вверх/вбок, клики, крупно) ·
**Таблица** (range card 0–2500, шаг настраивается) · **График траектории**
· **Сетка прицела** (точка прицеливания по поправкам, FFP/SFP с учётом кратности) ·
**Библиотека пуль** · **Журнал/Truing** · **Настройки** (единицы, язык).
Языки: українська, русский, English (Qt Linguist, исходники на English);
при первом запуске — по языку системы (uk/ru, иначе en), меняется в настройках.
Адаптивная вёрстка: телефон (вертикально) и десктоп (боковая навигация).

## Always / Never

**Always:** физика покрыта тестами с эталонами до перехода к UI;
`core` без Qt; все единицы внутри — СИ, конвертация только на границе UI;
каждая фаза — отдельная ветка + коммиты.

**Never (вне v1):** 6-DoF/MPM; Bluetooth (Kestrel, дальномеры);
облачная синхронизация/аккаунты; iOS/macOS; копирование баз из установщиков Strelok (`Data/Strelok`);
изменение папок-зеркал в `D:\Projects\ballistic_calc`.

Заметки:
- Ф7: логика экранов вынесена в toolkit-free `applogic` (тестируется в WSL без Qt); Qt-слой — тонкий адаптер. Linux: app собран в WSL (Ubuntu 26.04, Qt 6.10.2, GCC 15) без предупреждений; скриншоты через `balcalc --screenshot` (offscreen) — десктоп и телефон OK.
- Ф7: эмулятор нестабилен с аппаратным GPU → запускать с `-gpu swiftshader_indirect`.
- Ф2: направление ветра — ОТКУДА дует, по часовой от линии огня, 0 = встречный (12 ч), 90° = справа (3 ч); последняя зона — до бесконечности.
- Ф3: аэропрыжок и Кориолис без азимута (только горизонтальная составляющая) — сверх эталона, проверены поведенческими тестами.
- Ф1: прицел перпендикулярен LOS (как смонтирован), а не вертикально над стволом, как в py-ballisticcalc (разница h·(1−cos L), 3 мм/100 м при 20°).
- Ф1: на высоте сохраняется доля водяного пара воздушной массы (с ограничением насыщением), а не относительная влажность.
- Ф0: Qt выбирает compile SDK = новейшую платформу (android-37.0 preview) → закреплено QT_ANDROID_COMPILE_SDK_VERSION 35.
- Песочница сессии не даёт запускать `.exe`, собранные в этой сессии, → тесты гоняются в WSL; Windows-сборку проверяет пользователь.
- WSL-дистрибутив — Ubuntu 26.04 (не 24.04).
